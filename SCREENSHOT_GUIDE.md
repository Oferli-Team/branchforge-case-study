# BranchForge — Screenshot Guide

The published images were captured from a temporary local clone with synthetic branch names, file changes, and a demonstration commit. They use a thin desktop-window frame and the redesigned dark interface at 100% browser zoom.

## Selected sequence

1. **Status workspace** — lead image; establishes the product, navigation, staged/untracked state, and the primary repository workflow.
2. **Focused diff** — shows the code-oriented workspace, diff source, hunk controls, and line-selection workflow.
3. **Filtered history** — shows author/text/hash filtering and commit controls using only the synthetic portfolio author.
4. **Branch management** — shows branch creation, checkout, rename/delete controls, and a collapsed advanced-ref section.
5. **Operation journal** — shows a successful branch operation, runtime state, and the product’s recovery/diagnostics orientation.
6. **Compare** — shows an ahead/behind result, one synthetic commit, and a combined ref diff.
7. **Diagnostics and plugins** — shows capability checks, plugin lifecycle controls, release operations, and a correctly disabled LFS state.

## Capture rules for future updates

- Use only an isolated demo repository with synthetic content.
- Keep browser zoom at 100% and use a desktop viewport large enough to show the full two-column workspace.
- Capture at native/high resolution; do not add “4K”, FPS, device, or performance labels.
- Use a small, neutral desktop frame rather than a large laptop mockup.
- Keep the cursor away from text and important controls in still images.
- Filter history to a synthetic author before capture.
- Check paths, remotes, author metadata, logs, plugin registries, and notifications at full resolution before export.
- Do not fabricate capabilities that are disabled in the current environment; showing a disabled LFS state is accurate.
